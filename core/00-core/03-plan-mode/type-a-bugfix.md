## 2. 원인 분석

> ⛔ **원인 확정 게이트 (MUST — 통과 전 §3 수정 방안 작성·코드 변경 금지)**
> 아래 3개를 모두 충족해야 "원인"으로 적을 수 있다. 하나라도 비면 그건 *가설*이지 원인이 아니다.
> 1. **재현했다**: 실제 증상(§1 로그)을 내 손으로 재현했다. 재현은 §1의 **실제 파라미터**로 — 다른 입력으로 "되네?" 하면 오진된다.
> 2. **그 줄이 범인임을 관측했다**: 지목한 코드 줄이 *그 재현 실행에서 실제로 실행되어 나쁜 값을 만든다*를 로그·계측·쿼리로 확인했다. → **"코드가 존재함 ≠ 코드가 원인임."** grep으로 함수를 찾은 것은 증거가 아니다.
> 3. **반증 실험을 적었다**: 이 가설이 틀렸다면 무엇이 관측될지 한 줄로 적었다. 반증할 수 없으면 진단이 아니다.

- **분석**: (왜 발생했는지. 코드 흐름 추적 결과)
