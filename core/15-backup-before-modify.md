# 15. 수정 전 백업 규칙 (Backup Before Modify)

> 이 문서는 00-core.md에서 참조합니다.
> 신규 추가: 2026-07-15 (사용자 명시 요청)

---

## ⛔ 최우선 잠금 규칙

**빌드/수정 모드에서 소스 파일을 수정·생성·삭제하기 전에, 반드시 대상 원본의 백업을 먼저 생성한다.**

- 지침/문서(.clinerules) 수정도 대상에 포함된다.
- 백업 없이 소스를 직접 수정하는 것은 **지침 위반**이다.
- 롤백이 필요한 경우를 대비해, 작업 시작 시점의 원본을 보관한다(사후 복구는 `07.recovery-rules.md` 참조).

---

## 백업 절차 (수행 전 필수)

1. **대상 파일 식별**: 이번 작업에서 수정할 모든 소스/문서 경로를 먼저 확정한다.
2. **백업 생성**: 원본을 보존 위치에 복사한다(원본 그대로, 덮어쓰기 금지).
3. **위치 기록**: 백업 위치를 작업 계획서(계획 모드) 또는 작업 로그에 명시한다.
4. **그 후 작업 수행**.

---

## 백업 보관 위치 규칙

### A. 계획서가 있는 작업 (plan 폴더 존재)
- 보관 위치: `<plan_folder>/backup/<원본 상대경로>`
  - 예: `wordcloud_project/plans/2026/07/15_01_xxx/backup/web/templates/plans_kanban.html`
- plan 폴더 내 `backup/` 이 없으면 생성 후 복사.

### B. 계획서 없이 즉시 수정하는 작업 (ad-hoc)
- 보관 위치: 저장소 루트의 `backups/YYYYMMDD-HHMMSS/<원본 상대경로>`
  - 예: `backups/20260715-143000/src/routes/plans_routes.py`
- 단, `backups/` 는 배포 제외 폴더여야 함(유출 방지).

### C. 지침(.clinerules) 수정
- `00-core/15-backup-before-modify.md` 본문처럼, 수정 전 원본을 `backups/` 에 복사하고 변경 이력을 남긴다.

---

## 백업 대상 판단

| 대상 | 백업 필요 |
|------|-----------|
| 소스 코드(.py/.html/.js/.css 등) 수정 | ✅ 필수 |
| 신규 파일 생성(기존 파일 영향 없음) | ⛔ 불필요(원본 없음) |
| 지침(.clinerules) 수정 | ✅ 필수 |
| 임시/빌드 산출물(`.gitignore` 대상) | ⛔ 불필요 |

---

## 실수 방지 체크리스트

- [ ] 수정할 파일 경로를 모두 식별했는가?
- [ ] 각 원본을 백업 위치에 복사했는가?
- [ ] 백업 위치를 계획서/로그에 기록했는가?
- [ ] 백업 원본이 덮어써지지 않았는가(수정은 원본이 아닌 작업 복사본/원본 그대로 진행)?
