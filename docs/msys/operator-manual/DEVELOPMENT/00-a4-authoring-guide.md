## 0. 핵심 원칙 (이 5줄이 전부다)

1. **한 페이지 = 하나의 완결된 주제.** 섹션(`##`)이 페이지 하단에서 시작해 다음 장으로 새지 않는다.
2. **페이지 나눔은 작성자가 `---pb---`로 명시**한다. 자동 나눔에 맡기지 않는다(§4에서 이유 확정).
3. **한 블록 ≤ 한 페이지** (인쇄 가능 높이 기본 257mm). 넘치는 표는 헤더 반복 분할, 큰 이미지는 단독 페이지.
4. **표준 마크다운만 사용.** 인라인 `<style>`·rp_gen 전용 HTML·픽셀 폭 이미지는 떨궈지거나 넘친다.
5. **양식은 프론트매터 `reportTheme`로 지정.** CSS가 그리고, 수정은 Tiptap이 그 자리에서 담당한다.

## 1. 표준 양식 사양 (기본기 — 이 값이 정본)

보고서 양식은 `src/app/report-theme.css`가 구현한다(한국 공공기관 표준 보고서 양식 = rp_gen `report.css` / MSYS `<style>` 계열 이식). **작성 시 이 사양을 기준으로 한다.**

### 1-1. 용지·여백
| 항목 | 값 |
|------|------|
| 용지 | A4 세로 (210 × 297mm) |

| 요소 | 마크다운 | 크기 / 서식 |

`report`=네이비 #1B1760 · `meeting`=청록 #0F766E(제목 밑줄형) · `proposal`=파랑 #1D4ED8(제목 반전 밴드) · `technical`=슬레이트 #334155(제목 좌측 바) · `one-paper`=네이비(첫 인용문을 헤드라인 밴드로).

### 1-4. 원페이퍼(one-paper) 추가 규칙
- 프론트매터 `pageMode: single` → 한 장 연속 시트.
- **첫 번째 인용문(`>`)** 은 헤드라인 결론 밴드(상하 굵은 선, 가운데 14pt Bold)로 렌더 → 문서 맨 앞 결론 한 줄을 여기 둔다.

## 2. 절대 규칙 (지키지 않으면 페이지가 깨짐)

### 2-1. 왜 깨지나 (구조적 제약 2가지)
md_editor 편집기는 **Tiptap(표준 마크다운/HTML 스키마)** 위에서 돈다.
- **제약 A — 단일 블록은 쪼개지 못한다.** 자동 분할은 블록과 블록 *사이*에만 들어간다. **표/이미지/코드블록 하나가 한 페이지 높이보다 크면** 잘리지 못하고 용지 밖으로 넘친다(spill).
- **제약 B — 표준 마크다운만 인식한다.** 스키마에 없는 마크업은 저장/렌더 시 **조용히 사라지거나 텍스트로 뭉개진다.** 사라진 요소는 높이 측정에서도 빠져 페이지 계산이 어긋난다.

### 2-2. 페이지 나눔은 `---pb---` 토큰만 쓴다
- 수동 페이지 나눔 토큰은 **`---pb---`** (한 줄 단독, 위아래 빈 줄).
- ❌ rp_gen의 `<div class="pagebreak"></div>` 는 **인식되지 않는다**(Tiptap이 떨궈냄).
- 편집기에서는 슬래시 명령/툴바의 "페이지 나눔"으로 삽입 → 저장 시 `---pb---`로 왕복 보존.

### 2-3. 상단 인라인 `<style>` 금지 → 프론트매터 `reportTheme`
- ❌ 문서 맨 위 `<style>…</style>` 는 떨궈진다. md_editor는 문서마다 CSS를 심지 않는다.
- ✅ 대신 프론트매터 `reportTheme:` 로 양식을 지정(§3).

### 2-4. rp_gen 전용 HTML → 표준 마크다운 치환표 (정본)
| rp_gen 마크업 | md_editor 표준 마크다운 | 결과 |
|------|------|------|
| `<div class="headline">결론</div>` | `> 결론` (문서의 **첫 인용문**) | one-paper 테마가 헤드라인 밴드로 렌더 |
| `<table class="kpi">…</table>` | 표준 **4열 표** (`\| … \|`) | 테마 표로 렌더(요약 지표) |
| `<span class="att">붙임N</span> **제목**` | **`**[붙임N] 제목**`** (강조 라인) | 강조 문단 ※ 아래 주의 |
| `<div align="right">작성자</div>` | `**작성자**` (일반 라인) | 우측정렬은 생략 |
| `<p class="cap">※ 각주</p>` | **`> ※ 각주`** (인용/주 스타일) | 참고(주) 박스 |
| `<img src="…" width="900">` | `![대체텍스트](경로)` | 테마가 `max-width:100%`로 맞춤 |
| 상단 `<style>…</style>` | 프론트매터 `reportTheme:` | 양식 테마 적용 |

> **주의(2026-07-21 확정):** 붙임 배지는 **`**[붙임N] 제목**` 강조 라인**으로 치환한다. (이전 계획서에 있던 `## 붙임N`(h2 승격)은 지침 §2-4 치환표와 어긋나므로 **폐기**. 배지는 섹션 제목이 아니라 강조 라벨로 본다.)

> 헤드라인·KPI·붙임 배지의 *픽셀 단위 재현*은 표준 마크다운으로는 근사까지만 되고, 완전 동일은 Tiptap 커스텀 노드가 필요하다(§부록 로드맵). 본문·제목·표·개조식 등 **문서의 8할은 위 치환만으로 rp_gen과 동형**으로 나온다.

### 2-5. 이미지는 픽셀 폭 속성을 쓰지 않는다
- ❌ `width="900"` ≈ 238mm → 인쇄 가능 폭(기본 170mm) 초과, 옆으로 넘침.
- ✅ `![대체텍스트](경로)`. **이미지 파일이 실재하는지 반드시 확인**(없으면 높이 0 → 페이지 계산 어긋남).

### 2-6. 이미지 파일 배치 — 문서별 `img.<문서명>/` 폴더 (2026-07-21 확정, 단일 규칙)
문서에 이미지를 첨부할 때는 **아래 하나의 규칙만** 쓴다. 공용 폴더(예전 `manual_images/`처럼 여러 문서가 섞이는 방식)는 **폐기**한다.

1. **폴더:** 문서 `X.md` 의 이미지는 같은 폴더에 있는 **`img.X/`** (X = 확장자 제외 파일명) 하위에 저장한다.
   - 예: `MSYS_구축완료보고서.md` → `img.MSYS_구축완료보고서/fig1-boundary.png`
2. **참조:** 문서에서는 항상 **상대경로** `img.X/파일명.png` 로만 참조한다(절대경로·URL·`manual_images/` 금지).
3. **워크스페이스는 경로 입력(path mode)으로 연다.** — 이것이 규칙의 필수 전제다.

**왜 이 규칙인가 (엔진 근거):** md_editor는 상대경로 이미지를 `resolveImageSrcs()`(`src/lib/doc-image.ts`)가 문서 위치 기준으로 풀어 `/api/asset?root=…&path=…` 서버 라우트로 서빙한다. 이 변환은 `getRootPath()`가 값을 가질 때(=**path mode**)만 동작한다.
- **폴더 선택 버튼(handle mode)** 으로 열면 `getRootPath()=null` → 변환이 건너뛰어져 상대경로가 `localhost:3000/…` 로 요청되고 **404(이미지 깨짐)**.
- **경로 입력 "열기"(path mode)** 로 열면 `/api/asset`가 디스크에서 읽어 서빙 → **편집·인쇄·PDF 세 표면 모두 정상**.
- 따라서 이미지가 안 뜨면 대개 파일 문제가 아니라 **여는 방식(mode)** 문제다. 경로 입력으로 다시 열면 해결된다.

> 한 이미지를 여러 문서가 공유해야 하면 각 문서의 `img.<문서명>/` 에 **각각 복사**한다(문서 격리 우선 — 이동·삭제가 깔끔). 용량보다 규칙 일관성을 택한다.

## 3. 페이지에 맞추는 구성 규칙

### 3-1. 프론트매터로 양식·페이지 모드를 정한다
```yaml
---
title: "문서 제목"
reportTheme: report        # report | meeting | proposal | technical | one-paper | plain
# pageMode: single         # (선택) 진짜 한 장 원페이퍼일 때만. 생략 시 여러 장 분리(bunri)
---
```
- **여러 장 보고서** → `reportTheme`만 지정(페이지 모드는 기본 분리/bunri).
- **진짜 한 장 원페이퍼** → `pageMode: single`.

### 3-2. "한 블록 ≤ 한 페이지" — 실측 인쇄 가능 영역
| 여백 프리셋 | 여백 | 인쇄 가능 **높이** | 인쇄 가능 **폭** |
|------|------|------|------|
| 매우좁게(기본) | 20mm | **257mm** | 170mm |
| 좁게 | 30mm | 237mm | 150mm |
| 중간 | 40mm | 217mm | 130mm |

- 표·이미지·코드블록 하나가 위 '높이'를 넘지 않게 만든다(제약 A).
- 표가 한 페이지보다 길면 → 논리적 지점에서 **여러 표로 나누고 머리행(헤더)을 반복**한 뒤 사이에 `---pb---`.

### 3-3. 큰 이미지는 한 페이지를 통째로 준다
- 거의 한 페이지 높이인 다이어그램/캡처는 **앞뒤에 `---pb---`** 로 단독 페이지 배치.
- 이미지가 여러 장 몰리는 페이지(예: 화면 캡처 4장)는 **1~2장/페이지**로 제한하거나, 묶음 유지 시 자동 나눔이 이미지 *사이*에서 처리하도록 둔다(블록 경계라 깔끔).

### 3-4. 제목(섹션)이 페이지 맨 아래에 홀로 남지 않게
- `##` 섹션 제목이 페이지 하단에 걸릴 것 같으면 그 **앞에 `---pb---`** 를 넣어 다음 장 상단에서 시작(고아 제목 방지).

### 3-5. 개조식·표 세부
- `□`/`○` 문자를 직접 찍지 말고 **마크다운 목록**(`- 항목`, 중첩 `  - 항목`)을 쓴다. 테마가 □/○ 마커를 그린다. (문자를 직접 찍으면 항목마다 별개 블록이 되어 페이지 중간에서 쪼개지고, 마커가 이중으로 보일 수 있다.)
- 표 정렬은 구분선에 `:--:`(가운데)/`--:`(오른쪽)/`---`(왼쪽) 명시. 테마 표는 `table-layout: fixed`라 폭이 균등 분배된다.

## 4. 엔진 동작 이해 (2026-07-21 확정 — 중요)

작성자가 알아야 페이지가 왜 그렇게 나오는지 이해되는 부분.

### 4-1. 페이지 모드 3종
- **wide** : A4 아님. 자유 폭 편집.
- **ilche** (`pageMode: single`) : 한 장 연속 시트. 페이지 나눔 시각요소 전부 숨김.
- **bunri** (기본) : 여러 A4 흰 용지로 분리. `.a4-sheets`가 흰 용지를 격자(297+8mm)로 그리고 내용이 그 위로 흐른다.
- 프론트매터에 `pageMode: single`이 **없으면 무조건 bunri**다. (초기 화면도 bunri다 — "초기"는 다른 모드가 아니라 비동기 분할이 정착되기 **전**의 bunri일 뿐.)

### 4-2. 자동 나눔 vs 수동 `---pb---` (선 위치가 달랐던 이유)
- **수동 `---pb---`** → 격자에 스냅되어 **항상 같은 높이(용지 경계)**. 엔진은 수동 나눔을 절대 지우지 않는다.
- **자동 나눔**(내용 넘침 시 엔진이 삽입) → 그 페이지 **마지막 블록이 끝나는 자리**에 생긴다. 블록 크기가 페이지마다 다르고 `break-inside:avoid`로 큰 블록이 통째로 다음 장으로 넘어가 바닥이 들쭉날쭉 → **선 위치가 매 페이지 달라진다.**
- 그래서 원칙 0-2: **주제 경계마다 `---pb---`를 직접 넣어 자동 나눔이 안 생기게** 한다.
- **화면의 page-break 선은 bunri에서 숨김 처리됨**(`globals.css`): 흰 용지 간격이 이미 경계를 보여주므로, 위치가 흔들리는 구분선·라벨은 시각 잡음이라 안 보이게 했다. **정렬 여백은 유지**되므로 내용은 정상적으로 다음 용지로 넘어간다. (인쇄·PDF에는 원래 안 나온다.)

### 4-3. 테마 밀도가 자동 나눔을 유발한다
- report 테마 본문 12pt·행간 1.9 → 페이지당 약 32줄(257mm ÷ ~8mm). 원저자 11pt·1.6은 약 41줄.
- 즉 **원본에서 한 페이지였던 분량이 md_editor에선 넘친다** → 원본 `---pb---` 위치를 그대로 옮기면 그 전에 자동 나눔이 낀다.
- 대응: 페이지 배치는 **md_editor 실측 스크린샷 기준으로 다시** 잡는다(§5-5). 밀도 자체를 원본에 맞추고 싶으면 report 테마 폰트/행간을 조정(전 report 문서에 영향).

### 4-4. 엔진 수정 내역(참고)
- `use-auto-page-break.ts` : 콘텐츠 높이 계산에서 정렬용 주입 `marginTop`까지 제외 → 여백↔분할 **양의 피드백 루프 차단**(초기≠분리 요동 제거).
- `tiptap-editor.tsx` `useAlignManualBreaks` : `desiredTop = Math.ceil(actualTop/pageH)*pageH` — **인덱스가 아니라 실제 위치 기준** 격자 스냅(과삽입 시 거대 빈칸 제거).

### 4-5. ⚠️ 편집기 열린 채 파일 덮어쓰기 주의
외부(도구/스크립트)에서 `.md`를 고쳐도, **편집기에 그 파일이 열려 있으면 저장/자동복원이 옛 내용으로 되돌린다.** 파일을 외부에서 바꿨다면 **편집기 탭을 닫고 다시 열어야** 반영된다.

## 5. 변환 절차 (기존 rp_gen 문서 → md_editor)

### 5-1. 전역 치환 (문서 전체 일괄) — §2-4 치환표대로
1. 상단 `<style>` 삭제 → 프론트매터 `reportTheme: report`.
2. `<div class="pagebreak">` → `---pb---` (단, **주제 경계로 재배치** — 원본 위치 그대로가 아니라 §4-3 밀도 반영).
3. `<div align="right">` → `**작성자**` 일반 라인.
4. `<div class="headline">` → 첫 `>` 인용.
5. `<table class="kpi">` → 표준 4열 표.
6. `<span class="att">붙임N</span> **제목**` → `**[붙임N] 제목**`.
7. `<p class="cap">` → `> ※ …`.
8. `<img width="…">` → `![]()` (폭 제거, 파일 존재 확인).

### 5-2. `□`/`○` → 마크다운 목록 (§3-5)
`□ 내용` → `- 내용`, 중첩 `○` → `  - 내용`. 테마가 마커를 그린다.

### 5-3. 긴 표 분할 (§3-2) / 큰 이미지 단독 페이지 (§3-3)

### 5-4. 원본 보존
변환 전 원본을 **백업**한다(`*.style-backup.md` 등). 저장소가 git이 아니면 특히 필수. 원본 파일 덮어쓰기는 사용자 확인 후.

### 5-5. 실측 미세조정 (필수)
높이 추정은 이미지 크기·폰트 렌더로 ±1장 흔들린다. **분리 모드 스크린샷으로 페이지별 주제 완결·넘침·공백을 보고 `---pb---` 위치를 2회 내외 조정**해 확정한다.

## 6. 작성/변환 체크리스트

- [ ] 프론트매터 `reportTheme` 지정, 상단 `<style>` 없음
- [ ] 페이지 나눔 전부 `---pb---` (`<div class="pagebreak">` 잔재 0)
- [ ] `headline`/`kpi`/`att`/`cap`/`align` 를 §2-4 표대로 치환 (`att`→`**[붙임N]**`, `cap`→`> ※`)
- [ ] `<img width>` → `![]()`, 이미지 파일 실재 확인
- [ ] `□`/`○` → 마크다운 목록(`- `)
- [ ] 한 페이지보다 긴 표 분할 + 헤더 반복
- [ ] 큰 이미지 단독 페이지
- [ ] 각 블록이 인쇄 가능 높이(기본 257mm) 안에 들어옴
- [ ] 실측 스크린샷으로 `---pb---` 위치 확정 (자동 나눔 잔존 0 목표)

## 7. 검증 기준 (실행 결과로만 판정, 예측 금지)

| # | 항목 | 통과 기준 |
|---|------|----------|
| 1 | 주제 완결 | 각 페이지가 하나의 장으로 끝남(섹션이 경계를 넘어 이어지지 않음) |
| 2 | 넘침 없음 | 표·이미지가 흰 용지 밖으로 새지 않음 |
| 3 | 공백/백지 없음 | 의도한 주제 나눔 외 빈 페이지 없음 |
| 4 | 모드 일관성 | 초기/일체/분리에서 본문 시작 위치·기본 양식 동일 |
| 5 | 양식 적용 | 제목박스·섹션 강조선·표 헤더 회색 등 report 테마 반영 |
| 6 | 편집 유지 | 변환본을 Tiptap으로 그 자리에서 수정 가능 |
| 7 | 자동 나눔 잔존 | 수동 `---pb---`만 남고 자동 나눔(들쭉날쭉 경계) 없음 |
