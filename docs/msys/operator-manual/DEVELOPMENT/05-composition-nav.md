## 1. 메뉴얼 파일 구성 규칙

### 1.0 적용 대상·위치·명칭 규약 (공용 지침)

- 이 작성 지침은 **모든 프로젝트의 운영자 매뉴얼에 공용 적용**된다(`.clinerules`는 공용 서브모듈).
- **매뉴얼 위치(고정)**: `.clinerules/docs/<프로젝트키>/operator-manual/` 아래에 만든다.
  - MSYS → `.clinerules/docs/msys/operator-manual/`
  - 워드클라우드 → `.clinerules/docs/project_wordcloud/operator-manual/`
- 각 매뉴얼 폴더는 동일 구조: 진입점 `00-index.md`, 메뉴 문서 `NN-*.md`, 툴링 `build/`(print.css·MANIFEST.txt·build_integrated.py), 통합본 `integrated-manual.md/html`, 운영/구성 시나리오 문서(§1.5).
- **내용은 프로젝트 고유**: 본 지침의 예시(`mngr_sett`·`cd_cl`·`CD901` 등)는 **MSYS 예시일 뿐**이다. 각 프로젝트 매뉴얼은 **그 프로젝트의 실제 메뉴·데이터 모델을 코드(DDL·서비스·라우트)로 검증**해 채운다. **다른 프로젝트 내용 이식·추측·복붙 금지**(`03.plan-mode` #11 예측 금지 준용).

### 1.1 진입점 (제목 + 서론 + 목록 + 빠른 작업 색인)
- `00-index.md` **단일 파일**로 최상단 구성: 제목·서론(목적·대상·범위) + **목록(TOC)**(각 메뉴 상대경로 링크, §2 탐색 준수).
- **빠른 작업 색인(필수)**: 긴급 상황에서 운영자가 바로 찾도록 `## 이럴 땐 여기` 표를 둔다 — `상황 | 바로 갈 시나리오(링크)`. 예: "수집이 실패했어요 → [장애 대응 §2](07-troubleshooting.md)". 일상운영/장애대응의 대표 시나리오를 상황 키워드로 매핑.

### 1.2 메뉴별 파일
- **1메뉴 = 1파일** (`NN-menu.md`). 문서 구조 템플릿([01-structure.md](01-structure.md)) 준수.

### 1.3 탭 보유 메뉴 — 하위파일 방식
| 파일 | 내용 |
|------|------|
| `NN-menu.md` | 화면 구성 + **탭 목록/설명**(탭명·ID·역할 표) |
| `NN-menu.tab1.md` … `tabN.md` | 각 탭 상세(템플릿 기능 절차 적용) |

- 탭 파일명: `메뉴ID.tab{N}.md` (예: `08-api-key-mngr.tab1.md`, `05-mngr-sett.tab6.md`).
- 적용 예: `05-mngr-sett.md`+`tab1~6`, `04-common-menus/08-api-key-mngr.md`+`tab1~4`.
- `NN-menu.md`의 탭 표에서 각 탭 파일로 링크(§2).

### 1.4 부록
- `appendix/` 하위에 명령어 치트시트·설정 참조 배치.

### 1.5 운영 시나리오 문서 (종단 흐름, 필수)
개별 메뉴의 `운영 시나리오` 절([01-structure.md](01-structure.md) §4)과 별개로, **여러 메뉴를 넘나드는 종단(E2E) 흐름**을 담는 문서 세트를 표준으로 둔다.

| 표준 문서 | 담을 내용 |
|------|------|
| `NN-daily-operations.md` (일상 운영) | **Task 기반 E2E 시나리오**(예: 신규 수집→스케줄 등록→대시보드 확인→알림). 점검표/로그뿐 아니라 **단계·요소 이미지·확인지점**까지 |
| `NN-troubleshooting.md` (장애 대응) | 증상 → 진단 → 조치 시나리오(화면 근거 이미지) |
| `NN-backup-recovery.md` (백업·복구) | 백업·복구 절차 시나리오 |
| `NN-provisioning-scenarios.md` (구성·설정) | **신규 데이터/코드/키 추가 등 설정 작업**. 관리자 모드의 어려운 프로비저닝을 **정확한 순서·시점**으로 |

- 네 카테고리는 **최소 요건**. 점검표·명령어 나열만으로는 불충분 → Task 기반 시나리오 필수.
- **구성/프로비저닝 시나리오 규칙(필수)**: 이 시스템은 관리자 모드라 신규 추가 절차가 어렵다. "새 데이터/그룹/키를 추가하려면?"류 **설정 시나리오**를 반드시 포함하고, 각 시나리오는 **① 선후 순서(무엇을 먼저)** **② 시점(언제·선행조건)** **③ 의존관계(A가 없으면 B 불가)**를 표로 명시한다. 예: "그룹 코드는 상세코드의 상위 컨테이너라 **가장 먼저** 정의".
- 각 단계는 메뉴 문서/탭으로 **링크**, 조작 요소 이미지를 규칙 [02-image-capture.md](02-image-capture.md)로 첨부.
- 세 문서 모두 `00-index.md` 목록·`MANIFEST.txt` 등재(누락 시 통합본에서 빠짐).

## 2. 메뉴 간 탐색(내비게이션) 규칙

모든 메뉴얼 파일은 클릭 이동 링크를 포함한다.

### 2.1 공통 링크 배치
- **상단**: `↑ [목록으로](00-index.md)` — 진입점 복귀.
- **하단**: `← [이전: 이전메뉴](이전파일)` / `[다음: 다음메뉴](다음파일) →` (순서는 `MANIFEST.txt` 기준).
- **탭 파일 간**: `← 이전 탭 / 다음 탭 → / 메뉴로(NN-menu.md)`.

### 2.2 링크 작성 원칙
- 상대경로 사용(예: `../00-index.md`, `08-api-key-mngr.tab1.md`).
- TOC는 메뉴 한글명을 클릭 가능한 링크로.
