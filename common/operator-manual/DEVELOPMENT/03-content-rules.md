> 프로젝트별 고유 사항(특정 메뉴 작성 특이사항·실제 용어/상태코드 사전 값)은 이 문서에 두지 않는다. 각 프로젝트 `operator-manual/` 폴더의 프로젝트 전용 문서에 채운다(각 프로젝트의 `operator-manual/DEVELOPMENT/` 하위 전용 문서).

## 1. 공통 작성 규칙

### 1.1 한글 작성 원칙
- 모든 문서는 한글로 작성.
- 영문 용어는 괄호 병기: "대시보드(Dashboard)".
- 메뉴ID는 영문 그대로: `mngr_sett`, `api_key_mngr`.

### 1.2 테이블 작성 규칙
```markdown
| 컬럼1 | 컬럼2 | 컬럼3 |
|-------|-------|-------|
| 값1   | 값2   | 값3   |
```
- 표가 한 페이지보다 길면 논리적 지점에서 **여러 표로 나누고 머리행(헤더)을 반복**한 뒤 사이에 `---pb---`([00-a4-authoring-guide.md](00-a4-authoring-guide.md) §3-2). 표는 `table-layout: fixed` 라 폭이 균등 분배된다.
- 정렬은 구분선에 `:--:`(가운데)/`--:`(오른쪽)/`---`(왼쪽) 로 명시(00 §3-5).

### 1.3 경고/주의사항 강조
```markdown
> ⚠️ **주의**: 이 작업은 되돌릴 수 없습니다.
> 💡 **팁**: 단축키 `Ctrl+F`를 사용하세요.
> 🔴 **위험**: 삭제된 데이터는 복구할 수 없습니다.
```

### 1.4 개조식(목록)
- `□`/`○` 문자를 직접 찍지 말고 **마크다운 목록**(`- 항목`, 중첩 `  - 항목`)을 쓴다. `reportTheme` 가 □/○ 마커를 그린다(00 §3-5). (문자를 직접 찍으면 항목마다 별개 블록이 되어 페이지 중간에서 쪼개지고 마커가 이중으로 보인다.)

## 2. 용어·상태코드 사전 (운영자 필수)

> 운영자는 개발자가 아니다. 문서에 처음 등장하는 **전문용어·코드**(예: `Job ID`, `cron`, 상태코드류)는 **반드시 쉬운 말로 풀이**한다.

- **위치**: 코드가 적은 문서는 처음 등장 지점에 괄호 풀이. 코드/약어가 많은 문서는 하단에 `## 용어·코드 사전` 표를 둔다.
- **상태코드 표 필수 항목**: `코드 | 의미 | 운영자 관점 설명`.

| 코드 | 의미 | 운영자 관점 |
|------|------|------------|
| `[코드값]` | [무엇을 의미하는지] | [운영자가 봐야 할 조치·정상 여부] |

- 실제 코드값·예시는 프로젝트마다 다르다 — 각 프로젝트 코드 체계(DDL·서비스 코드 정의)를 실제 코드로 검증해 채운다(추측·이식 금지).
- 공통 코드/약어는 `appendix/`에 사전을 두고 각 문서에서 링크할 수 있다.
