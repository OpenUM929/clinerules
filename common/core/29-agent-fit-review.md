# 29. 에이전트 적합성 점검 (결과 검증 · 세션 종료 회고)

> **적용 대상 — Claude Code 서브에이전트(`.claude/agents/*.md`) 를 쓰는 저장소.** 정의 *파일*의 작성 규약은 [26-agent-definitions.md](26-agent-definitions.md), 정의가 **실행될 때** 밟는 0단계는 [28-agent-bootstrap.md](28-agent-bootstrap.md), 여기는 **쓴 뒤·안 쓰고 지나간 뒤에 하는 점검**이다.
>
> 두 구멍을 막는다 — ① 같은 유형을 메인이 반복해서 직접 처리하는데 담당 정의가 끝내 생기지 않는다 ② 서브에이전트 결과를 점검 없이 채택해 정의의 결함이 교정되지 않은 채 남는다.

---

## 1. 반복성 게이트 — FIT-1

신규·확장 제안은 아래 4문항에 **모두 "예"** 일 때만 낸다. 하나라도 "아니오"면 **제안하지 않는다** — 회고 결과는 FIT-4 의 「추천 없음」 한 줄로만 남긴다.

| # | 질문 (예/아니오) | "아니오"의 예 |
|---|------------------|---------------|
| R1 | 같은 유형의 작업이 과거에 **2회 이상** 있었고, 그 사례를 근거로 댈 수 있는가 | 이번이 처음이다 |
| R2 | 앞으로 다시 발생할 개연성이 있는가 | 1회성 조사·특정 버그 진단·일회성 데이터 확인 |
| R3 | 입력·출력 형태와 판정 기준을 정형화할 수 있는가 | 매번 산출물 형태가 다르다 |
| R4 | 매번 같은 가드레일(수치 재검증·원문 대조·금지 표현 등)을 반복 적용해야 하는가 | 가드레일이 그때그때 다르다 |

근거를 제시하지 못하는 "2회 이상"은 R1 **불충족**이다 — 기억이 아니라 사례를 댄다([17-hallucination-prevention.md](17-hallucination-prevention.md)).

## 2. 세션 종료 회고 — FIT-2~5

| 조항 | 내용 |
|------|------|
| FIT-2 | **세션 종료 시점 1회.** 종료 자체는 관측되지 않으므로 **마무리 신호가 온 최초 1회**에 수행한다 — 마무리 발화(그만·오늘 여기까지·정리해줘)·커밋 요청·세션 요약/압축 요청. 작업이 끝날 때마다 하지 않고, 한 세션에서 두 번 하지 않는다. 대상은 그 세션에서 **서브에이전트 없이 메인이 직접 수행한 작업** |
| FIT-3 | 제안 전 **카탈로그(`.claude/agents/README.md`)를 먼저 대조**한다([26](26-agent-definitions.md) §4). 담당했어야 할 기존 정의가 있으면 신규 제안이 아니라 「다음엔 그 정의로 라우팅한다」로 결론낸다. 범위가 겹치는 신규 후보는 내지 않는다 |
| FIT-4 | 후보는 FIT-1 을 통과한 것만 올린다. **세션당 최대 2건, 후보당 5줄 이내.** 후보가 0건이면 「반복성 미충족으로 추천 없음」 **한 줄만** 적는다 |
| FIT-5 | 추천은 **제안일 뿐이다** — 정의 파일 **자동 생성 금지, 자동 호출 금지.** 생성 여부는 사용자가 정한다 |

**후보 출력 항목(고정)**: 에이전트명(kebab-case) · 담당 범위 1줄 · 반복성 근거(어떤 작업이 몇 회) · 필요한 도구 · 내장할 가드레일 · 기존 정의와 겹치지 않는 이유.

## 3. 결과 검증 — FIT-6~9

| 조항 | 내용 |
|------|------|
| FIT-6 | 서브에이전트 결과는 **채택 전에** 점검한다. 보고를 액면 그대로 믿지 않는다 |
| FIT-7 | 점검 4항목 — ① 요청한 산출물이 **형식·범위대로** 나왔는가 ② 보고가 사실인가(파일 존재·수치·인용을 **표본으로 직접 확인**) ③ 정의가 정한 보고 형식과 **읽은 문서 목록**([28](28-agent-bootstrap.md) BOOT-6)이 지켜졌는가 ④ **역할 경계**를 넘지 않았는가(검증 역할이 파일을 고쳤는지 등 — [26](26-agent-definitions.md) AGT-6) |
| FIT-8 | 미달이면 원인을 셋으로 나눈다 — ⓐ **지시 부족**(정의는 그대로 두고 재지시) ⓑ **정의 수정·확장 필요**(같은 미달이 반복될 성질) ⓒ **신규 정의 필요**(그 역할이 아예 없음). ⓑ·ⓒ 는 **FIT-1 을 통과할 때만** 제안한다 |
| FIT-9 | 미달분을 메인이 **조용히 손으로 메우지 않는다.** 메웠으면 무엇을 메웠는지 보고에 남긴다 — 남기지 않으면 정의의 결함이 성공으로 기록된다 |

ⓑ·ⓒ 로 판정해도 이 문서가 정하는 것은 **제안까지**다. 정의 파일 작성·수정은 [26](26-agent-definitions.md), 지침 문서 수정은 사용자의 명시 요청이 있을 때만 한다([08-guideline-modification.md](08-guideline-modification.md)).

---

## 4. 검사

FIT 는 실행 시점 행동이라 **정적 린트 대상이 아니다**([28](28-agent-bootstrap.md) §5 와 같은 이유 — 린터는 파일에 적힌 것만 본다). 사람이 확인하는 지점은 두 곳이다.

| 확인 지점 | 무엇을 본다 |
|-----------|-------------|
| 세션 말미 | 회고 결과 — 후보(FIT-4 형식) 또는 「추천 없음」 한 줄이 있는가 |
| 결과 채택 보고 | FIT-7 점검 결과와 FIT-9 보완 내역이 적혔는가 |
