# 21. 프로젝트 격리 (지침 혼입 방지)

> 공통 지침을 새 프로젝트로 복사할 때 프로젝트명 치환을 빠뜨리면, 그 문서는 **남의 프로젝트를 가리킨 채 정상 문서처럼 남는다.** 실제로 이 방식으로 두 프로젝트의 지침이 양방향 오염된 사례가 있다.

---

## 1. 격리 규칙 — ISO

| 조항 | 내용 | 검사 |
|------|------|------|
| ISO-1 | `common/**` 문서는 `projects/` 경로를 **직접 참조하지 않는다**. 필요하면 `{{guideline.project_dir}}` 플레이스홀더 | `L1` |
| ISO-2 | `common/**` 문서에 [`PROJECTS-REGISTRY.md`](../PROJECTS-REGISTRY.md) 등록 프로젝트의 고유 **이름**(자기 프로젝트 포함) 금지 | `L2` |
| ISO-3 | `projects/A/**` 는 `projects/B/**` 를 참조하지 않는다 | `L3` |
| ISO-4 | `projects/` 직하에 자기 `<project_id>` 외 폴더가 있으면 위반 | `L4` |
| ISO-5 | 타 프로젝트 지침을 인용할 때는 "타 프로젝트 참조"임을 문서에 명시한다. 규칙으로 채택하려면 `common/` 으로 **승격한 뒤** 참조한다 | 수동 |
| ISO-6 | 프로젝트 지침 수정 요청이면, `project.json` 으로 확정한 `projects/<project_id>/` 외에는 **쓰기 금지** | 수동 |
| ISO-7 | `common/**` 에 특정 프로젝트의 **구조 가정**(폴더 계층·파일 경로·테이블명) 금지. 단 형식을 **정의하는** 문서는 **중립 예시**(등록 프로젝트 어디에도 실재하지 않는 이름)로 형태를 보인다 | `L6` — 타 프로젝트 **error** / 자기 프로젝트 warn |
| ISO-8 | `common/**` 에 특정 프로젝트의 **사고·릴리스 식별자**(요구사항 ID·버전 태그·커밋 해시) 금지. 단 형식을 **정의하는** 문서의 예시는 허용 | 수동 |
| ISO-9 | **금칙어 사전 자체가 검사 대상이다.** [`PROJECTS-REGISTRY.md`](../PROJECTS-REGISTRY.md) 가 없거나 `이름`·`경로·구조` 중 한 분류라도 못 읽으면 위반 | `L2` |

**ISO-2 가 자기 프로젝트명도 금지하는 이유**: "지금 이 저장소의 프로젝트니까 괜찮다"고 남겨두면, 그 문서가 다음 프로젝트로 복사될 때 그대로 따라간다. 오염은 항상 그렇게 시작된다.

**ISO-7 — 고유값은 이름만이 아니다**: "라우트 → 서비스 → 데이터접근 → SQL 매퍼" 처럼 특정 저장소의 폴더 사슬을 그대로 적은 서술은, 프로젝트명을 한 글자도 쓰지 않고 남의 프로젝트를 가리킨다. 실제로 이름만 검사하던 동안 이 형태의 오염이 전수 통과했다. 폴더가 없는 프로젝트에서는 그 문장이 **틀린 채로 정상 문서처럼 남는다.**

**ISO-7 의 중립 예시**: 명명 규칙·형식 정의 문서는 예시로 실제 형태를 보여야 한다. 그러나 그 예시가 등록 프로젝트에 **실재하는** 테이블·폴더 이름이면 예시가 아니라 오염이다(§3 조치표). 어디에도 없는 이름을 쓰면 형식은 그대로 보이면서 사전에 걸리지 않는다 — 비용 0 의 해결책이다.

**ISO-7 의 심각도가 갈리는 이유**: 에이전트 정의의 같은 검사(`A6`)와 맞춘다. **타 프로젝트 계층은 이 저장소에 존재하지 않으므로 그 문장은 이미 틀렸다** → error. 자기 프로젝트 계층은 지금은 맞지만 이식하면 틀린다 → 외재화 대상 warn.

**ISO-9 가 필요한 이유**: 사전이 비면 격리 검사(`L2`·`L6`·`A3`·`A4`·`A6`)가 **경고 없이 통째로 꺼진다.** 실제로 사전 파일이 없는 저장소에서 오염된 정의를 검사했더니 0건으로 통과했다. 사전 없음·형식 어긋남을 실패로 만들어야 "0건"이 신뢰된다.

**ISO-8 이 자동 검사가 아닌 이유**: `REQ-2604-011` 같은 값은 형식이 범용이라 사전으로 못 잡고, 형식 정의 문서([`06-git-rules/05-cr-id.md`](06-git-rules/05-cr-id.md))는 예시로 실제 형태를 보여야 한다. 자동 검사는 예시가 없는 에이전트 정의(`A7`)에만 건다.

---

## 2. 복사 이식 시 필수 절차

공통 지침을 다른 프로젝트로 옮길 때:

1. 옮길 문서에서 프로젝트 고유값을 찾아 `project.json` 키로 **외재화**한다.
2. 외재화가 불가능한 값이 남으면 그 문서는 공통이 아니다 → `projects/` 로 내린다.
3. 이식 후 린터를 실행해 `L1`~`L4` 가 0건인지 확인한다.

**치환으로 해결하려 하지 말 것.** 치환은 빠뜨릴 수 있고, 빠뜨린 것을 아무도 못 본다. 외재화는 빠뜨릴 자리가 없다.

---

## 3. 위반 발견 시

| 상황 | 조치 |
|------|------|
| `common/` 에 프로젝트 고유값 | 플레이스홀더화. 불가능하면 해당 부분을 분리해 `projects/` 로 강등 |
| `common/` 의 **예시**가 특정 프로젝트 경로 | 중립 예시(`projects/example/`)로 교체 |
| `projects/` 에 타 프로젝트 폴더 | 정본 저장소와 파일 목록·내용을 **대사한 뒤** 이관. 대사 없이 삭제 금지 |

> 타 프로젝트 폴더를 발견했을 때 곧바로 삭제하면 안 된다. 정본 저장소에 없는 파일이나 더 새로운 내용이 이쪽에만 있을 수 있다. 목록 차집합과 내용 해시를 모두 확인한 뒤에 처리한다.
