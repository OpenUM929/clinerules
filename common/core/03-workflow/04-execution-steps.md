# 워크플로우 실행 순서

모든 작업은 다음 순서를 엄격히 준수한다:

1. 관련 docs/ 문서 확인 (02-documentation.md 참조)
2. **요청 의도 분석 및 확인** ([request-analysis.md](02-request-analysis.md) 참조)
   - "새 기능 추가" vs "기존 기능 수정/버그 수정" 구분
   - 에러 메시지 있는 경우: 전체 맥락 확인
   - 모호한 요청: 상세화 요청 후 진행
3. 요구사항과 기존 설계 비교 → 충돌이나 모호함이 있으면 즉시 의문 제기
4. **영향도 분석 수행** (`common/development/impact-analysis-guide.md` 참조)
   - 변경 대상 모든 사용처 전수 검색
   - 의존성 및 영향 범위 분석
   - 롤백 계획 수립
   - 단계별 배포 계획 수립
5. 요구사항을 잘못 이해한 경우:
   - 즉시 "죄송합니다. 요청을 잘못 이해했습니다."라고 명확히 밝힘
   - 오해한 부분과 근거 문서 설명
   - 올바른 방향 제안
  6. 구현 후 테스트 실행 및 구체적 결과 보고
  7. **변경 적용 방식 안내 (재시작/F5)**: 소스 수정 작업 종료 시, 변경 파일 종류별로
     **'서버 재시작 필요' vs '브라우저 F5(새로고침)로 충분'**을 명시 안내한다.
     판단 기준은 [../../common/development/server-reload-guide.md](../../development/server-reload-guide.md) 참조
     (Python/.env/블루프린트/설치패키지 = 재시작, Jinja 템플릿/정적 자산 = F5).
     다중 파일 혼합 시 대상별로 구분 안내.
