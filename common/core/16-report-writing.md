# 📄 보고서 작성 공통 지침 (나침반 + 공통 규칙 + 양식)

> ⚠️ **이 문서는 모든 "보고서" 작성의 공통 진입점이다.**
> 보고서 종류를 파악 → 아래 §1 종류표에서 찾기 → 해당 **정본 지침/템플릿**으로 이동 → §2 공통 규칙을 항상 지키며 §3 공통 뼈대로 채운다.
> 개별 보고서 전용 규칙(영향도·감사 등)은 각 정본 문서가 오버라이드한다. **공통 규칙(§2)은 모든 보고서에 예외 없이 적용된다.**

| 보고서 종류 | 목적 | 대상 독자 | 정본 지침 / 템플릿 | 파일명·저장 위치 규약 |

## §2. 공통 규칙 (모든 보고서에 예외 없이 적용)

1. **파일 경로 표시**: 보고서를 작성/수정하면 **응답 최하단에 저장 파일 경로를 항상 표시**한다.
2. **독자 적합성(외부·비개발 독자일 때 필수)**: 인사처 등 비개발 독자 대상 보고서는
   - **건수·% 등 핵심 숫자와 결론을 맨 앞에** 둔다(방법론·근거는 뒤로).
   - **모든 수치에 해석 문장**을 붙이고, 내부 용어(티어·CLEAN·극성 등)는 **평문으로 치환하거나 용어 풀이표**를 둔다.
3. **집계값 vs 추정값 구분**: 전수 집계한 정확한 값과, 표본 기반 추정치(오차범위 존재)를 **명확히 구분 고지**한다. 추정치는 범위로 표기(예: `≲0.5%`, `+10~20%`).
4. **근거·재현성**: 수치는 **산출 절차·스크립트·시드·기준을 인용**해 "누가 다시 해도 같은 값"임을 보인다(주관 판단 아님). 표준 절차가 있으면 그 문서를 링크한다.
5. **정직 고지(과장·자축 금지)**: 완료/실패/생략을 있는 그대로, **한계·불확실성**을 명시한다. 유형·목록형 결과엔 필요 시 **"완전한 목록 아님"** 등 범위 한계를 밝힌다.
6. **참조 지침 명시**: 보고서 상단에 참조한 지침 문서 목록을 기재한다([02.documentation](02-documentation.md) §문서 최신성).
7. **이력형은 누적**: 개선/현황 보고서는 **단일 스냅샷을 덮어쓰지 말고 기간대별로 누적**한다(개선 역사 전량 보존).
8. **완료(DN) 보고는 실동작 검증 후**: 단위테스트만으로 완료 선언하지 않는다(실행 검증 전엔 진행/보류로 보고).
9. **산출물 범위 = 요청받은 것 하나**: 요청받지 않은 부속 문서(규격서·지면 예산표·근거대장·개정이력)를 파생시키지 않는다. **규격을 다루는 분량이 본문보다 많아지면 잘못 가고 있는 것**이므로 멈추고 보고한다. 지면이 한 장에 들어가는지는 mm 계산이 아니라 **분량 한도(항목 수·글자 수) + 인쇄 미리보기 1회**로 닫는다.

## §3. 공통 뼈대 (양식 — 종류 무관 기본 틀, 각 정본 템플릿이 세부 확장)

```
# <보고서 제목>

> 대상: <데이터/변경/작업> · 목적: <한 줄> · 작성일: YYYY-MM-DD
> 대상 독자: <내부 / 인사처 등> · 참조 지침: <문서 목록>

## 1. 한눈에 보는 결과 (핵심 숫자·결론 먼저)
   - 건수·% 표(외부 독자면 필수) 또는 핵심 결론 3~5줄

## 2. 용어 (외부·비개발 독자일 때 필수)
   - 보고서에 쓰인 내부 용어의 쉬운 정의표

## 3. 방법 / 근거 (재현성·데이터 출처)
   - 어떻게 측정/분석했나 + 집계값/추정치 구분 + 표준 절차·스크립트 인용

## 4. 상세 결과
   - 종류별 상세(영향도·테스트·감사 등은 정본 템플릿의 세부 표 사용)

## 5. 발견 · 원인 · 권고

## 6. 산출물 (파일 경로 목록)

## 7. 한계 (정직 고지)
```

---

## §4. 작성 절차

1. §1에서 보고서 종류를 특정 → 해당 정본 지침/템플릿을 연다.
2. §2 공통 규칙을 체크리스트로 적용한다(특히 외부 독자면 2·3항).
3. §3 뼈대 + 정본 템플릿 세부로 채운다.
4. 완료 후 응답 최하단에 파일 경로를 표시한다(§2-1).
