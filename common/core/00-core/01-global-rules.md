# ⛔ 전역 잠금 규칙 (모든 작업에 예외 없이 적용)

> 최종 개정 2026-10-29 (당일 제1차) — rev-261029-01

> 이 섹션은 Claude가 선의로 범하는 과잉 행동을 막기 위한 규칙이다.

## 규칙 목록

1. **지침 파일 자동 수정 금지**: 사용자가 명시적으로 "지침 수정해줘"라고 요청한 경우에만 `.clinerules/` 파일을 수정한다. 지침이 outdated처럼 보여도 수정하지 않는다.

2. **절차 자동 확장 금지**: 요청되지 않은 절차(영향도 분석, CR 보고서, 릴리즈 노트 등)를 자동으로 실행하지 않는다. 각 절차는 명시된 트리거 조건이 충족될 때만 실행한다.

3. **범위 외 코드 수정 금지**: 요청 범위 외 파일은 명백한 오타·문법 오류라도 수정 전 사용자에게 알린다. → 자세한 등급은 [01-legacy-protection.md](../01-legacy-protection.md) 참조

4. **Plan Mode 실행 금지**: Plan mode에서는 읽기만. "수행"이라고 명시적으로 요청할 때까지 대기.

5. **다건 요구사항 처리 후 항목별 요약**: 사용자가 여러 개의 요구사항·이슈를 한 번에(번호 매김·나열 등) 전달한 작업을 완료하면, 응답 마지막에 "요청 항목(원문 또는 요약) | 처리 결과" 형식의 표로 항목별 처리 결과를 정리한다. 요구사항이 1건뿐인 단순 작업에는 강제하지 않는다.

6. **운영 중인 프로그램의 기동 조건 불변 (신규 필수 설정 금지)**: 이미 배포·운영 중인 프로그램은 변경 후에도 **사용자가 아무것도 더 하지 않고** 지금처럼 기동되어야 한다.
   - 6-1. 사용자가 직접 넣어야 하는 **신규 환경변수를 만들지 않는다.** 기존 선택 환경변수를 필수로 바꾸는 것도 같다. 새 설정은 코드 기본값 또는 자동 생성으로 처리한다.
   - 6-2. 기존 설정의 **기본값을 제거해 기동을 막지 않는다** — 보안 강화 목적이어도 같다. 바꿔야 하면 사용자 개입 없는 자동 이관(기존 값을 코드가 판별해 그대로 이어 쓰기)으로 한다.
   - 6-3. 기존 동작에 없던 **부가 기능(기동 시 입력 프롬프트 등)을 요청 없이 붙이지 않는다.** 요청된 것만 구현한다.
   - 6-4. 위 금지에 걸릴 수 있는 변경이 불가피하다고 판단되면 **구현 전에** 사용자에게 묻는다.
   - 왜: 보안 강화를 이유로 코드의 비밀값 기본값을 없애 환경변수를 필수로 만들자, 이미 배포된 운영본이 기동 불가가 되어 4일을 잃었다. 이를 수습하려 기동 시 비밀번호 입력 등 원래 없던 기능을 덧붙여 더 꼬였다(2026-10-29 사용자 지시로 신설). 배포된 프로그램에 환경변수 추가를 요구하는 것 자체가 비정상 행동이다.
