# 04. 참조 검증 (링크·자산·경로)

> 나침반이 가리키는 곳에 갈 수 없으면 나침반 체계 전체가 무의미해진다. 실제로 최상위 나침반의 링크가 깨진 채 오래 방치된 사례가 있다.

---

## 1. 문서 링크

- 다른 문서를 참조할 때마다 **Glob 으로 실제 존재 여부를 확인**한다.
- 존재하지 않는 문서로 링크하지 않는다.
- 새 문서 폴더를 만들면 `README.md` 를 함께 만든다.
- 참조할 문서가 없으면 사용자에게 "어떤 문서를 만들어야 하나?" 질문한다.
- 상대 링크는 **그 문서 위치 기준**으로 해소되어야 한다. 저장소 루트 기준 경로를 보여주려면 링크를 걸지 말고 백틱 코드 표기를 쓴다.

## 2. 자산·경로도 동일하게 검증한다

문서 링크뿐 아니라 **이미지 등 자산 참조**와 **코드·스크립트에 하드코딩된 경로**도 실존을 확인한다.

| 대상 | 검증 |
|------|------|
| 이미지 참조 (`<img src>`, `![]()`) | 참조 파일이 실제로 존재하는가 |
| 스크립트의 입출력 경로 | 폴더가 실제로 존재하며, 문서가 참조하는 경로와 **동일한가** |
| 설정 파일의 경로 값 | 실존 여부 |

## 3. 깨진 참조 0건 대사

문서를 수정한 뒤 반드시 실행한다.

```bash
# 지침 저장소 전체 검사 (링크 K1 · 이미지 K2 포함)
python .clinerules/tools/lint_guidelines.py --severity error
```

특정 폴더의 이미지만 대사할 때:

```bash
grep -rhno 'src="images/[^"]*"' . --include=*.md | sed 's/.*images\///;s/"//' | sort -u > ref.txt
ls images/ | sort -u > have.txt
comm -23 ref.txt have.txt   # 참조되었으나 없음 → 반드시 0건
comm -13 ref.txt have.txt   # 보유하나 미사용 → 검토 대상
```

## 4. 실패 사례

> 캡처 스크립트의 저장 경로가 존재하지 않는 폴더를 가리켜, 실행해도 문서에 반영되지 않는 상태가 방치되어 있었다. **스크립트가 "정상 종료"해도 결과물이 목적지에 도달했는지는 별도로 확인**해야 한다.

> 파일명이 비슷하다는 이유로 대체 자산을 지정하지 않는다. **자산을 직접 열어 내용이 일치하는지 확인**한 뒤 참조를 수정한다.
