### FP (Function Point) 산정 기준

**간소화된 FP 산정:**
- 복잡한 테이블 대신 **작업 난이도 기반 점수 부여**:
  - **간단**: 1~3 FP (단순 수정, 텍스트 변경)
  - **보통**: 4~8 FP (새 기능 추가, 여러 파일 수정)
  - **복잡**: 9~15 FP (아키텍처 변경, 다중 모듈 수정)

**FP 세부 내역 포함 규칙 (CRITICAL):**
- 커밋 메시지와 CR 보고서에 FP 산정 시 **EI/EO/EQ/ILF/EIF 분류를 반드시 포함**
- 각 유형별 항목, 복잡도, FP 점수를 테이블로 작성
- 예시:
  ```
  FP: 3 (EI:0, EO:2, EQ:0, ILF:0, EIF:0)
  ```
  | 유형 | 항목 | 복잡도 | FP | 설명 |
  |------|------|--------|-----|------|
  | EO | 팝업 텍스트 출력 제한 | 낮음 | 1 | JS substring 적용 |
  | EO | CSS overflow 처리 | 낮음 | 1 | ellipsis/nowrap 추가 |

**20 FP/월 기준 (시간 환산):**
- 1개월 = 20 FP 처리 가능 (표준)
- 1개월 = 176H (22영업일 × 8H)
- **즉, 1 FP = 176H ÷ 20 = 8.8H ≈ 1영업일**

| FP | 예상 공수 (H) | 예상 공수 (영업일) |
|----|---------------|---------------------|
| 1 | 8.8H | 1일 |
| 3 | 26.4H | 3.3일 |
| 5 | 44H | 5.5일 |
| 10 | 88H | 11일 |
| 20 | 176H | 22일 (1개월) |

### 커밋 메시지 작성 시 적용
```
# 기능 작업 (feat, refactor)
✨ feat REQ-yymm-nnn: <변경 요약 72자 이내>

- 변경 상세 내용 1
- 변경 상세 내용 2

Refs: REQ-yymm-nnn
FP: 5 (EI:0, EO:3, EQ:1, ILF:1, EIF:0) | 공수: 44H | 작업유형: 기능 (feat)
```

```
# 버그 수정 (fix)
🐛 fix REQ-yymm-nnn: <변경 요약 72자 이내>

- 변경 상세 내용 1
- 변경 상세 내용 2

Refs: REQ-yymm-nnn
FP: - | 공수: 2.5H | 작업유형: 비기능 (fix)
```

> **비기능 작업 시**: `FP: -` 작성 + `공수: 3H` (실제 투입 시간)
