# 커밋 메시지 형식

> 상위 나침반 [`../06-git-rules.md`](../06-git-rules.md) 에서 분리.

## 커밋 메시지 형식

### 타입 프리픽스 (Conventional Commits 기반)

> `260625.txt`(Conventional Commits + 이모지 기반 `/commit` 커맨드 정의)를 지침에 반영.
> 기존 `REQ-yymm-nnn:` **선두 프리픽스**와 FP/공수 푸터는 그대로 유지하고, **앞에만** 이모지+타입을 덧붙인다.

- 첫 줄 형식: `<이모지> <타입> REQ-yymm-nnn: <요약 72자 이내>`
  - 명령형 어조, 원자적 커밋(1커밋 1주제), 분할 기준 준수
  - "Claude"·"Generated by AI" 등 **Claude 서명 미추가** 가드레일
- 표준 타입 집합:

| 타입 | 이모지 | 의미 | 실사용 여부 |
|------|--------|------|------------|
| feat | ✨ | 새로운 기능 | O |
| fix | 🐛 | 버그 수정 | O |
| docs | 📝 | 문서화 | O |
| style | 💄 | 포맷팅 | 미사용 |
| refactor | ♻️ | 리팩토링 | O |
| perf | ⚡ | 성능 개선 | 미사용 |
| test | ✅ | 테스트 | 미사용 |
| chore | 🔧 | 빌드/도구 | 미사용 |
| inquiry | ❓ | 질문/문의 | 템플릿만 |
| analysis | 🔍 | 분석/디버깅 | 템플릿만 |

> ⚠️ `inquiry`/`analysis`의 이모지 `❓`/`🔍`는 `260625.txt`·본 지침 어디에도 정의되지 않은 **신규 배정**(실행 시 사용자 승인). 상단 8종(feat~chore)과 그 이모지는 `260625.txt` 그대로.

### 기본 형식 (간단한 변경 시)
```
# 기능 작업 (feat, refactor)
✨ feat REQ-yymm-nnn: <변경 요약 72자 이내>

- 변경 상세 내용 1
- 변경 상세 내용 2

Refs: REQ-yymm-nnn
FP: N (EI:0, EO:N, EQ:0, ILF:0, EIF:0) | 공수: NH | 작업유형: 기능
```

```
# 버그 수정 (fix)
🐛 fix REQ-yymm-nnn: <변경 요약 72자 이내>

- 변경 상세 내용 1
- 변경 상세 내용 2

Refs: REQ-yymm-nnn
FP: - | 공수: NH | 작업유형: 비기능 (fix)
```

### 상세 형식 (복구/이력 추적이 중요한 변경 시) - e.txt 기반
> 복구 시 내용 파악이 용이하도록 상세 기록

```
REQ-yymm-nnn: <변경 요약 72자 이내>

## 현재 상태
> 변경 전 문제 상황, 버그 현상, 개선 필요성

## 완료된 것
> - [x] 완료된 작업 항목 1
> - [x] 완료된 작업 항목 2

## 진행 중인 것
> - [ ] 진행 중인 작업 항목

## 미결 결정사항
> 아직 결정되지 않은 사항, 추후 검토 필요 사항

## 다음 작업
> - [ ] 다음에 해야 할 작업

## 주의사항 / 이전 실수
> 이번 작업에서 피해야 할 점, 학습한 내용

## 관련 파일 경로
> - 파일경로/파일명 (변경유형: 생성/수정/삭제)

Refs: REQ-yymm-nnn
FP: N | 공수: NH | 작업유형: 기능/비기능
```
