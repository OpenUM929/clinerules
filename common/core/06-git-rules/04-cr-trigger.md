## CR 보고서 / 릴리즈 노트 생성 트리거

> ⚠️ **아래 조건이 충족될 때만 생성한다. 조건 미충족 시 자동 생성 금지.**

| 산출물 | 생성 조건 |
|--------|----------|
| CR 보고서 | 사용자가 `git commit` 또는 "커밋해줘"를 **명시적으로 요청**한 시점 |
| 릴리즈 노트 | CR 보고서 생성 후, 작업 유형이 **"기능 작업"(feat/fix/refactor)** 일 때 |
| 둘 다 생성 안 함 | 분석, 조회, 설명 요청 (inquiry / analysis / documentation / review) |

---

## 작업/커밋 확인 순서

### [작업 전] - 작업 시작 시 확인

1. **01-legacy-protection.md** - 레거시 코드 보호 확인
2. **00-core.md** - 작업 유형 분류 확인 → 올바른 절차로 안내

### [커밋 시] - 커밋 요청 시 확인

3. **CR ID 중복 체크** - `{{paths.cr_root}}` 폴더에서 기존 ID 확인 후 다음 번호 부여
4. **기능/비기능 작업 구분**
   - 기능 작업: FP(Function Point) 기반으로 개발 일수 환산
   - 비기능 작업: 맨먼스(Man-month) 기반으로 일자 정보 입력
5. **CR 보고서 작성** - FP 또는 맨먼스 기반 공수 산정

### 작업 유형 구분

| 구분 | 조건 | 공수 환산 |
|------|------|----------|
| **기능 작업** | feat, refactor | FP 기반 → 시간(H) 환산 |
| **비기능 작업** | **fix**, inquiry, analysis, documentation, review | **시간(H) 자체 계산** |

### 비기능 작업 정의

| 유형 | 설명 | 예시 | **공수 계산 (H)** |
|------|------|------|-------------------|
| **fix** | 버그 수정 | "버그가 안 고쳐져", "버그 발생" | **실제 투입 시간**: 디버깅 2H + 수정 0.5H = 2.5H |
| **inquiry** | 질문/문의 | "기본값이 뭐야?", "어떤 파일이야?" | **실제 투입 시간**: 조사 15분 + 답변 5분 = 20분 → 0.3H |
| **analysis** | 분석/디버깅 | "데이터가 안 떠", "에러 발생" | **실제 투입 시간**: 디버깅 2H + 수정 1H = 3H |
| **documentation** | 문서 확인/작성 | "문서 만들어줘", "설명해줘" | **실제 투입 시간**: 3페이지 × 15분 = 45분 → 0.75H |
| **review** | 코드/설계 리뷰 | "코드 리뷰 해줘" | **실제 투입 시간**: LOC 500 × 0.1분 = 50분 → 0.8H |

> **핵심**: 비기능 작업은 MM(맨먼스) 대신 **실제 투입 시간(H)**을 기록.
> - fix: 분석/디버깅 시간 + 수정 시간 합산
> - 예: `공수: 2.5H` (버그 수정)
