# 확인 결과 적립 — 재확인 루프(뫼비우스) 차단

> 상위 나침반 [`../17-hallucination-prevention.md`](../17-hallucination-prevention.md) 에서 분리.
> **확인을 안 해서 반복하는 게 아니다. 확인 결과를 파일에 남기지 않아서 반복한다.**

---

## 왜 이 문서가 생겼나 — 실제 사고

2026-08-05~06, 같은 산출물 폴더를 **10회 이상 재스캔**했다. 매번 확인은 했다. 그런데 확인 결과가 **응답(대화)에만** 남고 파일에 남지 않았다. 컨텍스트가 압축되면 결론은 사라지고 원자료만 남는다 → 다음 세션이 같은 조사를 처음부터 다시 한다 → **루프**.

| 증상 | 실제 원인 |
|------|-----------|
| 같은 폴더를 매 세션 다시 스캔 | 확정 사실이 산출물 JSON 수십 개에 흩어져 있고, **결론을 모은 단일 지점이 없다** |
| [ABS-7](09-data-absence.md) "이미 측정한 값을 먼저 소진한다"가 안 지켜짐 | 조회할 대장이 없으니 **"조회" 비용이 "재측정" 비용과 같다.** 실행 불가능한 규칙이었다 |
| 한쪽 폴더만 보고 "그건 없다"고 단정 | 같은 주제 산출물이 **두 폴더로 갈려** 있는데 어디에 무엇이 있는지 지도가 없었다 |
| 보고서 수치를 다음 세션이 또 검증 | 인용 근거를 **파일명까지만** 적어, 그 수치가 파일 어디서 나왔는지 다시 열어봐야 했다 |

**피해**: 사용자 컨텍스트를 대량 소모했고, 부분만 보고 낸 결론("전수 감사는 1개 연도뿐")이 **대외 보고서의 한계 고지에 실릴 뻔했다.** 실제로는 세 연도 전부 있었다.

---

## FL-1. 확인 결과는 **그 자리에서 파일에 적립**한다

원자료를 조회해 결론을 냈으면, 응답에 쓰는 것과 **동시에** 대장에 적는다. 응답만 하고 끝내면 소실이 확정된다.

- 위치: 그 작업의 산출물 폴더에 `_FACTS.md` (append-only, 수정·삭제 금지, 정정은 새 행)
- 1행 = 1사실. 필수 6요소:

| 요소 | 예 |
|------|-----|
| 주장 | 2023·2024·2025 세 연도 전량 필드 대조 실시 |
| 수치 | 102.6만 / 87.0만 / 74.0만 |
| **출처 파일 + 키** | `result/field_census_3y_260729.json` → `years.2023.n` |
| 범위 | 전수 (표본이면 모집단·표본수 병기) |
| 측정일 | 2026-07-29 |
| 한계 | 라벨 보존분만, 분모 상이 |

**출처는 파일명이 아니라 파일 + 키/행까지 적는다.** 파일명만 적으면 다음 사람(다음 세션의 나 포함)이 파일을 다시 연다 — 그게 루프의 씨앗이다.

## FL-2. 인용 순서를 고정한다 — **대장 → 없으면 측정 → 적립 → 인용**

1. 보고서·응답에 수치를 쓸 때 **먼저 `_FACTS.md` 를 읽는다.**
2. 대장에 없으면 원자료를 측정한다.
3. **측정 즉시 대장에 적는다.**
4. 그 다음에 인용한다.

3번을 건너뛰고 4번으로 가는 것이 루프의 유일한 발생 지점이다. 예외 없다.

## FL-3. 세션 재개·컨텍스트 압축 직후에는 **대장부터 읽는다**

압축 요약은 "내가 만든 파일 경로"는 남기지만 "무엇을 확인했는가"는 남기지 못한다. 재개 시 첫 행동:

1. 작업 폴더의 `_FACTS.md` · `_RESUME.md` Read
2. 거기 있는 사실은 **다시 확인하지 않는다**
3. 원자료 스캔은 대장에 **없는 것에 한해서만**

## FL-4. 탐색 범위를 대장 머리에 **명시**한다

같은 주제의 산출물이 여러 폴더에 흩어지는 것은 정상이다. 문제는 범위를 모른 채 한 폴더만 보고 결론을 내는 것이다.

- `_FACTS.md` 상단에 **이 주제의 산출물이 존재하는 폴더 전부**를 열거한다
- 부재 결론(「없다」)은 **열거된 범위를 전부 돌고 나서만** 낸다 → [ABS-1](09-data-absence.md)
- 새 폴더를 발견하면 그 즉시 목록에 추가한다

## FL-5. 대장에 있는 값의 **재측정은 사유를 적고** 한다

이미 적립된 값을 다시 재려면, 재는 이유를 대장에 먼저 적는다.

| 정당한 재측정 사유 | 정당하지 않은 것 |
|---|---|
| 원자료가 갱신됨 | "기억이 안 나서" |
| 측정 스크립트의 결함 발견 | "확실히 하려고" |
| 다른 분모·조건이 필요함(→ 별도 행으로 적립) | "혹시 몰라서" |

## FL-6. 사용자가 **"또 확인하네"** 라고 하면 즉시 멈춘다

원자료 조사를 계속하지 않는다. 그 시점의 행동은 다음 셋뿐이다.

1. 조사 **중단**
2. 지금까지 확인한 것을 **대장에 적립**
3. 대장 기준으로 답하고, 남은 미확인 항목을 **명시**

"한 번만 더 보면 확실해진다"는 판단이 반복의 실체다. 확실해지는 것은 확인이 아니라 **적립**이다.

---

## 체크리스트 — 원자료를 열기 직전

- [ ] `_FACTS.md` 를 먼저 읽었는가
- [ ] 이 값이 대장에 이미 있는가 (있으면 열지 않는다)
- [ ] 없다면, 측정 후 **적립할 것**을 지금 정했는가
- [ ] 출처를 **파일 + 키/행**까지 적을 준비가 됐는가
- [ ] 「없다」를 쓸 예정이라면 FL-4 의 폴더 목록을 **전부** 돌았는가

> 조사는 끝내는 것이 아니라 **남기는 것**으로 끝난다. 남기지 않은 조사는 하지 않은 것과 같다.
