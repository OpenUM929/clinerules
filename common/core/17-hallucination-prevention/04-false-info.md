## 3️⃣ 거짓 정보 감지 및 제거

### 의심 표현 리스트

| 표현 | 검증 필요 | 확인 사항 |
|------|---------|---------|
| "신규 추가" | ⚠️ 높음 | 계획서에 정말 없는가? |
| "완전히 새로운" | ⚠️ 높음 | 계획서 전체를 읽었는가? |
| "강화된" | ⚠️ 중간 | 양쪽 문서의 해당 섹션을 비교했는가? |
| "처음 도입" | ⚠️ 높음 | 계획서에는 언급되지 않았는가? |
| "~에만 있음" | ⚠️ 높음 | 반대쪽에 정말 없는가? |
| "X개 추가" | ⚠️ 높음 | 개별 항목을 하나씩 확인했는가? |

### 일반적 환각 패턴

#### 패턴 1: 가정으로 작성
```
❌ "일반적으로 보고서에는 성능지표가 포함됩니다."
   → 이 보고서에 정말 있는가?

✅ "이 보고서의 5.3절에 성능지표가 있습니다."
   → 실제로 읽고 확인함
```

#### 패턴 2: 기억에만 의존
```
❌ "앞서 본 계획서에는 사용자 만족도가 없었던 것 같습니다."
   → 확실하지 않으면 말하지 말 것

✅ "계획서 p.1~4를 읽었을 때 사용자 만족도 항목이 없습니다."
   → 실제 읽은 결과만 작성
```

#### 패턴 3: 부분만 읽고 전체인 척
```
❌ "보고서에 ROI 분석이 없습니다."
   (사실: 마지막 섹션에 있는데 못 읽음)

✅ "보고서 p.1~500을 읽었는데 ROI 분석이 없습니다."
   → 범위를 명시하면 검증 가능
```
