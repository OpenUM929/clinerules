# 23. 나침반(Compass) 규약

> 규칙은 있었으나 집행 장치가 없어 80줄 상한 위반이 72건까지 쌓였다. 하위 폴더를 만들어 놓고 본문을 그대로 둔 문서(222줄)도 있었다. 이 문서의 모든 조항은 **린터 검사 항목과 1:1 대응**한다.

---

## CMP-1. 나침반 판정 — 구조 기반

다음 중 **하나라도** 해당하면 나침반이다. 문서 안의 선언 문구와 무관하다.

| 조건 | 예 |
|------|-----|
| 동명 하위 폴더가 존재 (`X.md` + `X/`) | `03-workflow.md` + `03-workflow/` |
| 파일명이 `00-*.md` | `00-core.md` |
| `README.md` 이고 형제 md 가 2개 이상 | `03-workflow/README.md` |
| 저장소·프로젝트 진입점 | `CLAUDE.md`, `projects/<id>/README.md` |

나침반 상단에는 배지를 둔다(판정 근거가 아니라 독자 안내용):

```markdown
> 🧭 **나침반 문서** — 내용을 담지 않고 위치만 가리킨다.
```

> 선언 문구로 판정하지 않는 이유: 선언을 빠뜨린 문서가 검사 대상에서 통째로 빠진다. 실제로 선언을 가진 파일은 5개뿐이었고, 구조상 나침반인 문서는 그보다 훨씬 많았다.

---

## CMP-2. 줄수 상한

| 종류 | 상한 | 초과 시 |
|------|------|---------|
| **나침반** | **60줄** (하드) | 즉시 위반. 예외 없음 |
| **상세 문서** | 80줄 (경고) / **160줄** (하드) | 80~160 은 경고 — 주제가 혼재하면 분리. 160 초과는 위반 — 분리 필수 |

이 조항이 [`10-project-compass.md`](10-project-compass.md) 및 [`08-guideline-modification/03-document-separation.md`](08-guideline-modification/03-document-separation.md) 의 줄수 기준에 **우선한다.**

**80 단일 기준을 버린 이유**: 실측 위반이 72건이라 아무도 지키지 않았다. 지켜지지 않는 규칙은 규칙이 아니다. 나침반은 60으로 조여 "설명하지 말고 가리키라"를 물리적으로 강제하고, 상세 문서는 160을 넘을 때만 강제해 검사가 실제로 작동하게 한다.

---

## CMP-3. 나침반 콘텐츠

| 허용 | 금지 |
|------|------|
| 제목·배지 | 절차 서술(1. 2. 3. 단계) |
| 트리거 목록 (최대 10줄) | 코드 블록 |
| 라우팅 표 (`작업 유형 → 경로`) | 체크리스트 |
| 하위 문서 목록 표 | 예시·시나리오, 경고·교훈 문단 |

금지 항목이 필요하면 그것은 상세 문서의 몫이다.

---

## CMP-4. 분리 작업의 완료 조건

네 단계를 **모두** 마쳐야 완료다. 3·4를 빠뜨리는 사고가 반복됐다.

1. 하위 폴더 생성 (이름 = 나침반 파일명에서 `.md` 제거)
2. 내용을 주제별 파일로 이동
3. **원본에서 이동한 내용을 삭제**하고 라우팅 표로 대체 ← 누락 빈번
4. **원본이 60줄 이하임을 확인** ← 누락 빈번

## CMP-5. 링크

| 조항 | 내용 |
|------|------|
| CMP-5-1 | 상대 링크는 **그 문서 위치 기준**으로 해소 가능해야 한다 |
| CMP-5-2 | 저장소 루트 기준 경로를 보이려면 링크를 걸지 말고 백틱 코드 표기로 적는다 |
| CMP-5-3 | 존재하지 않는 문서로 링크하지 않는다 |
